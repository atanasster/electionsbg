# Procurement query semantics — version 1

Implementation decision record for plan step 0. Version `procurement-records-v1` identifies the population independently of legacy dashboard counts.

- Contract statistics count stored `contracts.key` records with `tag='contract'` and `consortium_role IS DISTINCT FROM 'member'`. Ordinary and carrier records remain. This is recorded awards, not a claim of deduplicated legal contracts. Unknown supplier identities do not remove otherwise valid records. A procedure is a distinct tender УНП; an amendment is its own record/event.
- Current contract value sums the existing normalized `amount_eur`, with null coverage reported. Member participation has a separate count and no attributed revenue; full consortium value is never summed across members. Existing framework allocations remain intact and are identified as ceilings. No ingestion/re-keying is part of this feature.
- Default date is contract record date, tender publication date, complaint filing date or act date respectively. Bounds are half-open ISO calendar dates. Signature/deadline queries need explicit verified date basis. Related complaint/act periods never replace the primary period.
- Exact-one-bid means recorded `number_of_tenderers=1`. Report all-record and positive-known denominators separately. Zero, negative/invalid and missing counts are separate. Raw prevalence is not the adjusted weak-competition check or the existing competitive-procedure benchmark.
- A named risk uses its served cache/catalog definition, availability and broader baseline. AND/OR/NOT use SQL three-valued truth. Composite known status follows the resulting truth value rather than requiring every constituent to be known. Contract grades, buyer grades and supplier grades remain distinct.
- KZK counts distinguish complaint number, act number and procedure УНП. Recorded upheld outcomes may include partial/mixed acts; they do not establish full party success. Preserve protected manual/date-only outcome values and derive effective refusal/suspension on read only.
- Buyer-sector classification uses versioned existing institution rosters. Subject classification uses explicit CPV/topic definitions and coverage labels. Health buyers are МЗ+НЗОК, not all hospitals; АПИ is a buyer, not all road work. Generic healthcare needs buyer/subject clarification. Road subject starts with road-work prefixes 452331 and 452332; medical goods/services are separate labeled subjects rather than an invented comprehensive healthcare census. Specific road repair and equipment requests use narrower supported prefixes/topics or clarification.
- Numeric results, applied query, data revision and population version travel together. Saved answers are historical; links rerun the same definition against current data and disclose revision changes. Missing data/capability cannot become a broad query or zero result.

Independent fixtures live in `ai/tests/fixtures/procurement-query.json`. Their arithmetic is asserted before serving implementation; production metrics are never hardcoded from the audit snapshot. Road prefixes were checked against the local 2026 tender shards: 45233142 is road repair, 45233161 sidewalks, 45233162 cycle paths and 45233262 pedestrian zones. The broad subject label must therefore include streets, paving and pedestrian/cycle works; “road repair” specifically uses 45233142. Missing/mismatched mapping coverage is unavailable rather than guessed.

Implementation detail: signing-date queries follow `realSignedDate`: a date equal to record date is treated as unavailable because ingestion backfills it. This conservatively excludes genuinely same-day signatures too. Signing-value queries retain the existing current-value fallback and must disclose it.

Tender award-over-estimate follows the existing scorer: awarded sum / estimate strictly greater than 1.10. Equality does not fire. Its SQL projection is checked against the TypeScript scorer at the threshold. The served cache and source-revision stamp rebuild in one SQL snapshot; queries reject a stale source revision.

Open/closed-at-instant queries require publication by that instant and a known deadline. Cancellation is the currently recorded state; the corpus does not reconstruct historical cancellation transitions. Every such response carries this limitation.
