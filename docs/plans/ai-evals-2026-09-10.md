# AI router evaluation — 10 September 2026

Expanded the public eval page for the current Gemini 3.5 Flash-Lite assistant and the 228-tool registry. These are live Google Gemini API responses, not simulated results. The prior artifact is preserved as a historical experiment.

## Measured results

431 bilingual cases per run: all 399 registry examples, 20 independently authored diagnostic cases, 6 held-out argument cases, and 6 unsupported requests. Same frozen suite in both runs. 862 baseline calls; 864 revised calls including two transport-only retries after HTTP 503. No model mistakes were selectively retried. The revised initial report preserves the failures; the final report contains the successful retries and `previousErrors`.

|---|---:|---:|---:|---:|
| Exact tool selection | 94.4% | 96.1% | 93.7% | 95.6% |
| Usable call | 91.9% | 96.1% | 91.4% | 95.4% |

All six held-out cases passed in both languages in the revised run. This is too small to estimate generalisation precisely. These cases were frozen before the baseline; their results were not used to edit descriptions.

## Implemented fixes

- The production catalogue now provides parameter descriptions, required/optional status, types, allowed values, explicit bounds and defaults. Previously it exposed only names, so the model could not know that `metric` must be `arrears` rather than “overdue liabilities”.
- The output instruction explicitly requires bare names and nested `args`. Previously outputs such as `waterServices()` and top-level entity fields failed validation.
- An explicit `{"tool":null,"args":{}}` is now available for unsupported requests and missing required entities. The cloud provider honours it instead of falling back to a keyword-matched tool. Malformed replies and provider failures retain the deterministic fallback.
- Clarified NGO signal codes, municipal fiscal metric codes, poll accuracy versus its trend, beneficiary ranking versus programme absorption, settlement versus province procurement, and the limited capabilities of `rankPlaces`.
- Regenerated all 228 semantic tool vectors from the revised metadata. Historical retriever scores were not relabelled or recomputed.
- The page shows before/after results, separate group metrics, raw per-case failures, provenance hashes, retry counts, and remaining limitations. Earlier models and retriever experiments are in a dated archive.

## Remaining problems and proposed solutions

1. **Ambiguous reference labels.** `nationalResults:2` asks specifically for seats, for which `parliamentSeats` is reasonable. `budgetFunction:2` says only “Defence spending”; `judiciaryWorkload:2` asks for the busiest courts; `transportSpending:2` asks where railway money goes; `municipalTransfers:1` overlaps the newer distribution tool. The census example asks for population without specifying Census 2021 versus address registration. Keep these strict scores as measured. For a future suite, independently review acceptable tools or rewrite the questions with an explicit basis, then version the suite and rerun both baselines. Do not change a label to reward the model after seeing its output.
2. **Missing context in registry examples.** “This company”, “this MP” and generic person questions have no required identity in an isolated prompt. The revised model appropriately abstains on many of these but the legacy example label expects a tool. Supply a fixed prior conversation or score a clarification outcome in a separately versioned suite. Do not invent identities.
3. **Generic ranking still steals specialised questions.** `regionalInvestment` is still misrouted to `rankPlaces` in both languages; the basket/GDP question misroutes in English. The latter tool silently defaults an unsupported indicator to unemployment. Descriptions alone did not solve this. Give ranking a closed capability schema, reject unsupported indicators with clarification, and route only after that validation; retain explicit EU-funds and basket/GDP regression cases.
4. **Year scope and cycle type.** One BG authored query for turnout over all of 2024 becomes `turnoutSeries(years=1)`; a local-election example returns numeric `cycle:2023` when the validator expects a string. Add semantic date-scope checks before execution and a reviewed cycle coercion policy. The current eval deliberately does not loosen validation to accept these errors.
5. **Coverage beyond routing.** This benchmark does not execute tools, exercise their data endpoints, evaluate narration, or measure the complete deterministic/model pipeline. Next: immutable tool-response fixtures, missing-data/clarification cases, conversation replay, and end-to-end assertions on scope, provenance and grounded answers. Registry examples are in-distribution and carry no gold argument values; “usable” for those means parser acceptance, not semantic proof.

## Reproduce

```sh
npm run ai:eval:current -- baseline
npm run ai:eval:current -- revised
# Retry only transport failures, requiring identical model, suite and prompt hashes:
npm run ai:eval:current -- revised data/ai/evals/runs/<revised-run-directory>
```

Requires the repo-local `GEMINI_API_KEY` in `.env.local`. Requests go to the same direct Gemini OpenAI-compatibility endpoint and through the same server `payload()` settings as production: temperature 0, minimal reasoning, 120 output tokens. It does not bypass the public proxy or reuse user sessions. Four concurrent requests, at most 1,000 case calls per invocation. Successful outputs are never retried on resume. Runs containing API errors cannot replace the current public artifact.

Raw reports and exact prompts are under `data/ai/evals/runs/`. The suite and prompt hashes match across a resumed run; baseline/revised suite hashes match each other. The original runner recorded the repository commit at completion, so the committed prompt snapshots and registry hashes are the primary provenance for these measurements (other workspace work was proceeding concurrently).

One pass per variant, with no statistical significance claim. Prompt-token usage increased from 8,747,952 to 11,842,101 across the 862 successful responses; completion tokens fell from 13,680 to 12,227. The provider did not supply a dollar cost, so no measured cost is claimed. Longer descriptions trade input cost for clearer calls.

## Validation and release

36 focused unit tests passed; the cloud-provider harness passed, including the explicit-abstention regression. Final AI typechecking and production build passed. Desktop/mobile browser checks passed in BG/EN and light/dark mode, with no page errors or document overflow. The revised prompt also passes the production 96,000-byte input limit with an additional 8,000-character message in both languages.

Release requires both updated AI hosting and the eval JSON files under `data/ai/evals/` in the data bucket. The page code alone cannot update bucket-served results. No deployment was performed in this task.
