# AI chat routing fixes and realistic evaluation, 2026-09-10

## Implemented

- Replaced arbitrary ranking indicators with eleven declared capabilities and separate ascending/descending order. Legacy supported phrases normalize without changing their metric/geography/direction. Unsupported phrases return clarification before fetching data; neither unemployment nor GDP is a fallback metric anymore.
- Added a semantic check so a valid GDP ranking cannot answer a basket/GDP or EU-funds question. Two exact specialist names emitted in the indicator slot are accepted as reviewed aliases only when they carry no extra filters. Arbitrary names and extra constraints are rejected, never fuzzy-matched.
- Numeric local-election years normalize losslessly to a known cycle string. Unknown years, fractional numbers and conflicting aliases are rejected. The reviewed `municipalFiscalRanking.n` alias maps to its declared `count` field.
- Calendar-year turnout requests accidentally sent to a rolling series are resolved by the existing deterministic election router, preserving all ballots in the year. Other unsupported anchored-series scopes clarify. The provider regression actually executes both 2024 ballots.
- Person profile/connections/wealth now declare the required name. Invalid person calls clarify instead of falling through to a keyword tool. A bare personal-pronoun request cannot execute an invented identity; actual prior conversation context remains available.
- Reviewed six ambiguous registry questions by narrowing their wording to the documented tool capability, and eleven entity-free questions by expecting clarification. Original registry examples and previous measured artifacts remain unchanged; the review overlay is explicitly versioned in the new suite.
- Added 40 bilingual pairs: 24 everyday civic questions, eight clarification/unsupported-action questions and eight conversation follow-ups. They cover informal wording, requested counts, calendar scope, named companies/people/places, topic changes and inherited filters. They are hand-written simulations, not user logs. With existing examples/challenges, the suite has **471 pairs / 942 responses**, **228 tools**, and **53 argument-annotated cases per language**.
- Added fixed-data execution checks for metric, order, geography, omitted missing values, provenance, multi-ballot scope, missing-ballot disclosure and rejection of an invented narration number. These supplement routing scores; they are not live-endpoint validation of every tool.
- Updated the page with the reviewed groups, conversation context, reviewed-question labels, raw response details, and the distinction between raw selection and validated/normalized calls. Both comparison rows use identical suite and scorer hashes.

## Actual measurements

| Metric | Earlier prompt EN | Final EN | Earlier prompt BG | Final BG |
|---|---:|---:|---:|---:|
| Raw tool selection | 96.8% | 97.0% | 97.2% | 96.0% |
| Usable call after production validation | 96.6% | 97.2% | 97.5% | 96.2% |
| Annotated arguments | 98.1% | 98.1% | 98.1% | 94.3% |

Final groups: authored diagnostics **20/20 each language**; original held-out checks **6/6 each**; new everyday questions **22/24 each**; new clarification/action cases **8/8 EN, 7/8 BG**; new conversation cases **8/8 EN, 7/8 BG**. Thus the 40 newly added pairs pass **38/40 EN and 36/40 BG**. The six original unsupported-action cases all pass in both languages.

**There is no overall improvement claim.** The final BG result is lower than the earlier-prompt baseline by 1.3 points. These are single stochastic passes, despite temperature zero, and the added/diagnostic questions have been inspected during development. They are not an independent generalization benchmark. Runtime safeguards prevent several incorrect executions even where strict model-abstention scores remain failures.

The first revised run regressed to 96.6% EN / 95.8% BG usable calls, exposing specialist names in the ranking field, `n`/`count` confusion and continued calendar-scope mistakes. It remains archived; the next run followed targeted production fixes. The final run retried **10 transport errors only**, preserving their initial responses and leaving successful outputs untouched. It made 952 API requests for 942 final outputs. Final transport errors: zero.

The final run's last two semantic safeguards were validated by replaying the saved responses, not by another model invocation. Both baseline and revised outputs were replayed through exactly the same production normalizer. Raw model selection is still separate from normalized usable calls, and a rejected/invalid personal call does not earn explicit-abstention credit. The unchanged original reports remain the raw measurement record.

## Remaining errors

Examples include a misspelled Varna argument in a BG conversation, confusion between budget overview/execution/variance, occasional invented tool names, legacy examples that overlap nearby tools, and a model-supplied person name in a context-free BG pronoun question. The latter is blocked at runtime. A specialist ranking alias with extra `n` is deliberately not repaired: dropping an explicit constraint silently is not acceptable. A model returning null for a supported question also remains a failure.

Broader evaluation still needs independently authored unseen questions, repeated trials, more fixed endpoint responses and live source-coverage checks. This change does not claim to execute and validate all 228 tools against production or measure every narrated answer.
